# 9P2000.vx

The messages VectraOS nodes speak to each other beyond 9P2000 (D78),
each frozen here when the change that first uses it lands (D151). 9p(5)
is the manual's account; this file is the record of what is frozen, and
since when.

## Negotiation

A client asks `Tversion "9P2000.vx"`; a VectraOS server reached through
an authenticated (Noise IK) listener answers `9P2000.vx`, a plain
listener and every foreign server `9P2000`. There is no feature list:
an extension is a pair of types from 128 up, T even, R the next, and a
server that doesn't know a T-message answers it `Rerror "unknown
message"`, after which the client does without it on that connection.

## Frozen

### Trename, Rrename (128, 129), 2026-10-30

    size[4] Trename tag[2] fid[4] newdirfid[4] name[s]
    size[4] Rrename tag[2]

Moves fid's file into the directory newdirfid as name, replacing a file
of that name there. Afterwards fid names the file where it went. A
rename between two mounts on the server is refused `Invalid
cross-device link`. First user: FDIO's rename(2) on an import, through
the import's fs protocol (gate(2)).

### Conventions of 9P2000 that a node gives meaning to

- A Twstat whose fields are all "don't touch" makes the file durable:
  fs(4)'s sync (Plan 9's convention; any dialect). First user: FDIO's
  fsync(2) on an import.
- A Twstat of the length alone resizes the file (9P2000's own). First
  user: FDIO's ftruncate(2) on an import.
