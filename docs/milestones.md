What each milestone contains, and its exit test, are defined in [04 §5](04-bootstrap-toolchain.md#5-milestones-to-hello-world) (M1–M3) and [04 §6](04-bootstrap-toolchain.md#6-after-m3) (M4–M15); this file tracks progress against them. A step's commit is recorded in the commit after it (a commit cannot name its own hash).

**Review pass** (2026-10-02, after M4; `002a9a8`): a read of the first-party code M4 added, in eight areas, its findings fixed where they were defects, with tests (ctest 333 checks, proctest 97, rctest 37, and host tests in `rc_test`, `eval_test`), and what was left recorded in Known gaps below. Among the fixes:
- **Kernel.** `channel_call` knows whether its request was read rather than looking for it by address (a freed block reused); `task_exec` holds both tasks against thread starts until the address spaces have moved; a completed wake is not overwritten by an interrupt; a thread stopped at an exception saves its FP/SIMD and TLS before its packet goes, so a debugger reads them, and what it sets is loaded; `thread_suspend` reaches every thread, and pokes until a newly started one parks; a debugger's writes into code copy the mapping once; aarch64 stepping follows the thread, so a stepped `svc` is reported.
- **procfs.** The profiling ring's header is read once and bounded (a process could fault procfs), and given only after procfs's own challenge shows in the process's memory; procfs takes no faults of its own; svcd takes no notes; crash directories are bounded (16 MiB, 5 s a call to tmpfs); `setsid`, `mem`, wait records and stale debug packets after a detach.
- **The musl back end.** Arguments and environment past 64 refused or carried (4096), never cut; `writev` and `sendmsg` totals checked; a forked child's file that was removed is joined through its directory, and one that cannot be is EBADF; signals: a blocked or ignored one ends no call, one that comes just before a wait ends it, handlers run as the program's code, fork forgets only the parent's pending ones, exec and `posix_spawn` keep what is ignored and the mask; `select`, `ppoll`'s timeouts, `munmap`'s length, `dup2` to a bad descriptor, `SO_RCVTIMEO`, a second `connect`.
- **Servers.** ptyd's masters counted on every open, output held for room rather than dropped, ^D as a position, not a NUL; 9P: an open fails when the server's open-file table is full, locks are all-or-nothing, by mode, and go with any close; holds run out; `nsd` takes a message's connectors whole or not at all; an unmount keeps the connections binds still use.
- **rc and gsh.** A pipeline's `$status` of 0s and `|`s is true; a stage's files stay open until it runs, its redirections come after its pipe, and a pipeline in `` `{} `` runs only its own stages; `$0`, `ifs=()`, `\` at the end of a line anywhere, long scripts and switches, and out of memory as an error.
- **dbg and vx-debug.** Bounds that cannot wrap, `INT64_MIN / -1`, DWARF line headers and truncated expressions, the event's thread, and a program too large to load said so.
- **build.** Ports built against musl's headers rebuild when they change; bootfs's limit is an error; a prompt= is not matched against output from before the typing.

**Exit test (proposed):** a C program built against `vectra-musl` forks, execs, pipes and waits; a shell script (`gsh` as rc; dash only if rc cannot fill the role) and Lua run in the POSIX userland; `dbg -c` stops at a breakpoint and prints a backtrace; a crashing program leaves a crash directory.

**File system review pass** (2026-10-03, after step 5; `cdd7164`): a read of vx-fs, `fsd`, `host/vxfs` and the paging of steps 5a–5d, in eight areas. Its critical and high findings fixed, with tests; the medium and low ones recorded in Known gaps below. The fixes:
- **The Bε tree.** Splitting a node's first child could leave the parent's keys out of order: keys a lookup could not find while the block was cached, and a tree that would not parse once it was read again. The first part now keeps the parent's key only when it is not above its own first key. `vxfs_tree_test` re-parses every node from the device, and makes this split.
- **Commit and mount.** The commit's phase 6 (11 §6) was missing: the backup superblock and the footers were durable only at the next commit, so a crash then and another in the next commit could leave the volume unmountable, or roll it back onto blocks already reused. The barrier is there now; mount makes the other superblock and any arena copy that does not match the mounted one's again, durably, before anything is allocated; and it tries the older superblock if the newer's arenas will not load. The power-cut test cuts again, three times and at a quarter of the barriers, in two commits made after each first cut (the old code fails it).
- **A full volume.** Running out of space was the volume's sticky error: everything since the last commit lost, and nothing could be removed to recover. Each operation now asks first (`vxfs_room`, an upsert's slack and its data blocks) and is refused with the new `VX_ERR_NO_SPACE` (`ENOSPC`, "file system full") having changed nothing; an operation that frees may use half of each arena's reserve; the allocation log may always take the next block it needs. A file of any size is removed a chunk at a time.
- **Hostile images.** A snapshot's height is checked (a write recursed on it); arenas must lie between the superblocks and clear of each other; a log's blocks must be its arena's.
- **The file layer.** A rename over a file someone has open (or mapped) keeps it as an orphan, as POSIX does; a rename deep in a tree is a refusal past 65536 levels, not a verdict on the volume.
- **fsd.** Open counts are kept per file, not per node id (which holds the user and the attach): a remove through one attach no longer destroys a file open through another. `/adm/users` with 127 users and no `none` wrote past the table. Only the permissive attach bypasses `setattr`'s rules; adm's members may still give owners.
- **Paging.** A shrink freed pages that a mapping made at that moment could still map: it now makes them absent under the lock, takes them out of every mapping, and only then frees them, `task_map` checks the size again under the lock, and resizes are one at a time. Only the pager may resize (`pager_op RESIZE`; `vmo_op` on a pager's VMO is `ACCESS`), since any writer could shrink a file everyone maps. A page request the port has no room for is asked again, not lost. Writeback asks for dirty ranges until there are none (it stopped at 64, then dropped the rest), and an entry's idleness is looked at before its writeback. A file's VMO is its size: `Rmap` says how much there is, and a client maps no more, so no one can grow a cache with pages of zeros.
- Tests: `vxfs_tree_test`, `vxfs_vol_test` (repairs, the fallback, hostile superblocks), `vxfs_file_test` (rename over an open file, a 600-block remove, a 5000-deep rename, a full volume emptied), `vxfs_crash_test` (second cuts), `vxfs_test`; ktest (resizes by the pager only, a full port), ctest on `fsd` (rename over an open file, writeback past 64 ranges, a mapping past the end, owners and groups), `fsdadm.rc` (a file open through `%home` removed through `home`, a users file of 127).

**Exit test (proposed):**
- QEMU boots the ISO, `install` puts VectraOS on a blank virtio disk, and the machine reboots from that disk.
- A program writes under load and QEMU is killed mid-commit. The next boot mounts at once, `check` is clean, and every file synced before the kill is there.
- `/cfg` is snapshotted, changed and rolled back, and yesterday's `home` is read through the dump view.
- Two processes share a file through `MAP_SHARED`.
- The disk driver is killed during a copy and restarted, and the copy completes intact.

## Known gaps

Deferred deliberately, each with where it is due:

| Gap | Effect now | Due |
|---|---|---|
| 9P replies always use arena offset 0 | Pipelined 9P requests would overwrite each other's replies; the client does not pipeline yet | M6 (the pipelined client) |
| No `Tflush` in the 9P client; a timeout only where a connection sets one (`procfs`'s crash directories) | A read held by a server (`ping` with no reply, a `listen`) waits until it is answered | M6 (the pipelined client) |
| No per-client connection limit | One client can take all 16 of a server's ring connections | Before M10 (swarm) |
