# D151. 9P2000.vx: the fs protocol and Node's watch carried between our nodes, an extension at a time, each with its first user (2026-10-30, decided by the owner; extends D78, D148 §1.5)

D78 made 9P2000 the core and reserved `9P2000.vx` for what our nodes say
to each other beyond it, as new message types, never as changes to
9P2000's. D148 put its design in V7, as one design before any of it is
built. This is that design.

## What stands

9gate already asks for `9P2000.vx` in Tversion and falls back to
`9P2000`; nothing yet differs between the two. Between two nodes an
import carries Node's reads, writes, walks, creates, removes, stats and
listings (names, sizes, times), and renames within a directory (wstat).
What a local client has and a remote one doesn't:

- **fs(4)'s protocol**, which the export doesn't serve and the import
  doesn't speak: typed attributes (`getAttribute`, `setAttribute`,
  `removeAttribute`, listings with them), `rename` between directories,
  `resize`, `sync`, and queries (`query`, `live`, `declareIndex`,
  `indices`). FDIO's rename, truncation and fsync go through it, so on an
  import `mv` between directories fails, and so would a tier-1 program's
  `ftruncate` or `fsync`.
- **Node's `watch`**: the import refuses it (`unsupported`), so nothing
  watches a remote file or directory.
- **Node's `memory`**: refused too, so no program runs from an import
  (cpu(8) BUGS: copy it first), and no file of one is mapped.
- **Bulk**: the import already bridges its channels' rings to 9P reads
  and writes; each is at most 32 KiB (the export's msize is a Node
  message's), and one connection runs every message through one serial
  chain each side (roadmap V7: about 138 MB/s node to node, whatever the
  window).

## Proposed

### 1. How extensions are negotiated

One dialect, `9P2000.vx`, as now, with no feature list in the version
string (NeoVectra's `+dref +map …` was a list; ours has one peer kind).
An extension is a pair of message types from a range of our own, above
9P2000's (128 and up). A server that doesn't know a type answers it
`Rerror "unknown message"`, and the client then does without it for that
connection: a newer node and an older one still talk, each extension
degrading as its absence does today. 9P2000's messages are never
changed, and a `9P2000` peer (v9fs, 9front) never sees one of ours.

### 2. Each extension waits for its first user

As NeoVectra's rule was: an extension's messages are frozen, in
`docs/proto/9p2000.vx.md`, when the change that uses them lands, with
that user. Until then the list below is a sketch.

| Extension | Messages | Carries | First user |
|---|---|---|---|
| **rename** | `Trename fid name newdirfid newname` → `Rrename` | fs's `rename` between directories | FDIO's `rename` on an import (`mv`, a tier-1 program's `rename(2)`) |
| **resize, sync** | `Tresize fid size`, `Tsync fid` | fs's `resize` and `sync` | FDIO's `ftruncate` and `fsync` on an import |
| **attributes** | `Tgetattrs fid names`, `Tsetattrs fid attrs`, `Tdelattr fid name`; `Tlistattrs fid cursor max names` (a listing with them) | Node's typed attributes, in Node's own encoding (Taisce's kinds) | Taisce's S2 (V7 step 7): a volume's changes received on another node keep their attributes |
| **watch** | `Twatch fid since` → one `Rwatch` with the events since, held until there are some; the client asks again | Node's `watch` | not yet named: the swarm's discovery (V7 step 6) may be it |
| **query** | `Tquery fid text scan` → matches; `Tlive …` held as `Twatch` is | fs's `query` and `live` | none in V7: waits |
| **lease** | NeoVectra's read lease (`Tlease`, `Rbreak`) | client caching by `qid.version` | none in V7: waits (a `cfs` in cpu sessions) |

Two things need no message:

- **memory** is the import's: asked for a file's memory, it reads the
  file whole into a VMO of its own and gives that, a private copy, as
  NeoVectra's `map` did for a remote server: no remote node can stall a
  page fault. Its first user is cpu(8)'s: a program run straight from
  `/mnt/term`.
- **bulk**: a larger msize, so one message moves more than 32 KiB
  through the per-connection chain, is the measured lever, not a new
  message. It needs the export to read more than a Node message at once
  (through the file's ring, `NodeFile`), and is judged against the
  node-to-node read it would raise.

### 3. What V7 builds (the owner's choice, 2026-10-30)

In this order: rename, resize and sync, with FDIO as their user; the
import's memory as a private copy; typed attributes now, with Settings
(system/settings) read and written through an import as their user,
Taisce's S2 their second. watch waits for a user (the swarm's discovery
may name one); query and lease wait for theirs. The larger msize is
measured first, as the export on rings was.

### 4. Only between our nodes

A plain listener (D148 §2) never speaks `9P2000.vx`: it answers
`9P2000` whatever a caller asks, so the extensions travel only over
Noise IK, between nodes that know each other's keys.

Not chosen: 9P2000.L's messages for the same things (D150); a feature
list in the version string (one peer kind, and unknown types already
degrade); carrying fs's protocol as IPC frames inside a 9P stream (two
wire formats on one connection, D6).
