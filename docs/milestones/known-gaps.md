# Known gaps

Deferred deliberately, each with where it is due (moved from [milestones.md](../milestones.md) on 2026-10-08):

| Gap | Effect now | Due |
|---|---|---|
| No per-client connection limit | One client can take all 16 of a server's ring connections | Before M10 (swarm) |
| POSIX programs see no file owners: `Tgetattr` reports uid and gid 0 (`getuid` and its kin are the user's users(6) id since 6e1c3) | `fsd` keeps owners and checks permissions, but `ls -l` and `stat` show root's | When `Tgetattr` is made from `stat`'s owners and the users table |
| Identity is advisory: a program names who it attaches as | `fsd`'s permissions stop mistakes, not a program that names another user | M10 (`keyd`) |
| The wall clock: x86_64 only (QEMU's aarch64 tables list no RTC, and there is no PL031 driver); set once at boot from the RTC, a step change, never slewed or written back; nothing orders services after it is set; an ACPI device's driver gets only its interrupt's line (an extended IRQ's polarity and trigger are not passed), and a device with a choice of lines gets the first | On aarch64 dates read as 1970; a service started before the clock is set stamps 1970 times (rtctest waits for it) | A PL031 driver with a table that lists it; NTP through `netd`, with slewing; setting the RTC with its first user |
| `fsd` holds at most 32 snapshots open by fids at once; a removed user keeps its place in fsd's users table until fsd restarts (6d5c) | A 33rd snapshot held at once is refused until a fid on another goes; a users file can then name 127 users less those removed since fsd started | A slot generation in the node id, if 32 held at once proves too few |
| All-stop (6d6a) freezes the threads that exist when a thread stops: one made while the rest are stopped runs; `dbg` has no thread-specific breakpoints, and `step` steps only a thread stopped at an event | A program that makes threads while stopped in the debugger runs those | A thread-creation event, as gdb's, when the desktop debugger needs one (M14) |
| Scheduling (6d6c): limits are the machine's until keyd; lower bands starve under higher ones; no tiers, NUMA domains, driver core masks or IRQ steering off reserved CPUs; a context is charged its threads' kernel time too; donation (6d6c2) reaches a server thread only as its port wait ends or as it reads the request, so one busy elsewhere runs at its own intent until then; one loan per thread, the highest; an answered loan lasts until the server next blocks or its slice ends | One program can take all of the realtime budget or every CPU but the first; a busy background server can delay a realtime call | M10 (per-user budgets); `/sys/cpu` topology; inheritance into a running server when measured |
| aarch64 under parallel load (several QEMUs at once): QEMU prints `virtio: zero sized buffers are not allowed` in about half the runs of posix, fsdnvme, acpiarm, block and distd together, never alone; and now and then a scenario's harness child dies (`FAIL: the harness itself failed`) with the guest's log clean. Both seen back to 6d6b (found in 6d6c2), unattributed | A flaky default-set run; a virtio driver may queue an empty buffer | Find the driver (QEMU's `virtqueue_map_desc`) and the harness's `die()`, with the next test step |
| A ring server's connections: one client may take every slot a server has (the Rust port's U1) | A program can deny a server to the rest until it lets go | M10: keyd's authentication, and quotas per user |
| `task_find` walks every task, and checks each one's line to the root, for each lookup: listing all the tasks (procfs's `/proc`) is quadratic in their number (the Rust port's U2) | Slow listings with many tasks; none at today's counts | When it is measured: a tree or table keyed by id |
| A cycle of channels (or rings) holding each other's handles is never freed: references are counted, nothing collects cycles; a channel already refuses its own end or its peer, as Zircon's does, which ends the simplest (the Rust port's U3) | A program that makes such a cycle leaks those objects for as long as the system runs | Not planned: Zircon has the same, and leaves it to programs not to make one |
| vx-9p's shared table of open files (posix) holds 256 for the whole server, and any client can fill it (seen in 6d5c: it, not fsd's own table, which now grows, was the limit) | Opens refused for every client of that server until files are closed | A table that grows, or a share for each connection, with the posix layer's next pass |
| A hostile volume image can still make `fsd` free live blocks (frees trust the generations and the freed chain on the disk), spin through a cyclic deadlist chain (bounded by the device's size), or make the checker slow (quadratic in snapshots); the fuzzer parses blocks and replays logs, and never mounts a crafted image | Mounting a crafted disk can damage that disk, never fault `fsd`; only the system volume, which the system made, is mounted today | 6d (a mount-level fuzz target); the checker on media not the system's |
