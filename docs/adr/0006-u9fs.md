# ADR-0006: u9fs, vendored as a host test tool

Status: accepted, 2026-10-01. The import was reviewed by James Kane, 2026-10-01 (`VENDOR.ndb`).

## Context

M3 asks that the 9P stack be tested against one stock 9P2000 server, so that `vx-9p` is not tested only against itself (04 §5). The candidates were 9front's `exportfs` (Plan 9 only), `diod` (9P2000.L only, and not packaged for Fedora 44) and `u9fs`, the Plan 9 project's own 9P2000 server for Unix.

## Decision

- `u9fs` is vendored unchanged under `third_party/u9fs`: the Plan 9 Foundation's tree at commit `ed1a9c2` (2025-10-28), `sys/src/cmd/unix/u9fs`. Upstream has no release tarball, so `VENDOR.ndb` pins the directory's git tree id (`git.tree=`), which the fetched files reproduce.
- It is a **host test tool only**: `build` compiles it into `out/host/u9fs` for the `u9fs` scenario. It is never part of an image.
- It builds as upstream left it except for two constants its `rune.c` uses and nothing defines (`Bit5` and `Runemax`, from an unfinished change to 21-bit runes). `build` supplies Plan 9's values on the command line (`-DBit5=2 -DRunemax=0x10FFFF`), so the tree stays byte-identical. It compiles as GNU C89, with warnings off: it is old code, not ours, and not under the house rules.
- `u9fs` serves `/` and confines itself only with `chroot`. The harness therefore runs it in an unprivileged user namespace (`unshare -r`), chrooted into a fresh copy of the test fixtures that also holds the one-line `etc/passwd` and `etc/group` its user lookups read, with `-a none -u vectra -n`.

## Review notes

About 6 kLOC. It reads 9P on its standard input and writes on its standard output; it makes no network connections and runs no other programs. It opens `/dev/urandom`, and `/etc/u9fs.key` only for p9any authentication, which the tests do not use. With `-u`, it never changes user. Licence: Lucent Technologies' permissive notice (`LICENSE`); Plan 9 has been under the MIT licence since 2021.

## Consequences

- `vx-9p`'s client meets a server written by others. Already one finding: Plan 9 servers refuse an attach as `none` until a connection has authenticated, so dialed connections attach as `vectra` (VectraOS has no user names before `keyd`, M8).
- Interoperability is tested in QEMU only, through `guestfwd`; a host without unprivileged user namespaces cannot run that scenario.
