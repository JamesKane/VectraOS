# ADR-0015: Lua 5.5.1, vendored unchanged, as `/bin/lua`

Status: accepted, 2026-10-06 (proposed 2026-10-02). The import's code review is still to be recorded (`VENDOR.ndb`, `reviewed.by=pending`).

## Context

M4 step 5 puts Lua in the POSIX userland (04 §6), and its exit test runs a Lua script there. Lua is the scripting language VectraOS keeps (the hot-reload decision does not replace it). It is about 30 kLOC of portable C with no dependencies but a C library, so it is the first program built against `vectra-musl` that VectraOS did not write. ADR-0003 asks for pinned, reviewed source with one ADR per import.

## Decision

- **Lua 5.5.1**, the latest release (2026-07-24), is vendored unchanged under `third_party/lua`: the whole release tree (`src`, `doc`, `Makefile`, `README`). 5.5 rather than 5.4.9: nothing here has 5.4 code to keep working, and the 5.5 line is where fixes go first. Licence: MIT.
- **Provenance.** Lua's releases are not signed. The tarball's sha256 is the one lua.org publishes on its download page (fetched over HTTPS), and every source file was compared with the `v5.5.1` tag of `github.com/lua/lua` (commit `7579fc9d`): all identical, `luac.c` aside, which only the release has. When reviewing, confirm the checksum against a second fetch, and compare against the tag again.
- **The build** is `./build`'s, from `ports/lua/port.ndb`: the source set and flags of Lua's `src/Makefile` for its `posix` platform (`-std=gnu99 -O2 -Wall -Wextra -DLUA_USE_POSIX`), with frame pointers kept, as for musl (ADR-0007). Its sources are compiled once per architecture and cached, as musl's are; `lua.c` is linked with them and `vectra-musl` into `/boot/bin/lua`, statically. Not `LUA_USE_LINUX`, which adds `dlopen`: C modules are built in or absent. Not `luac` until something precompiles chunks.
- **`./build` gains vendored POSIX programs**: a port's `program=` records name programs built from its `sources=` and their own, placed in `boot/bin` beside the first-party programs. sbase (step 5b) uses the same records.
- **Tests**: `tests/qemu/lua.ndb` runs `tests/user/luatest.lua` under svcd in the POSIX namespace: the language, the standard libraries, files in `/tmp`, `require`, the environment and the arguments. Script tests are a new kind of `with=` entry: a manifest and a script, with no program of their own.

## Known limits

- `os.execute` and `io.popen` run `/bin/sh -c`, and there is no `/bin/sh` until `gsh` is remade as rc, or dash is vendored (step 5's note). They fail cleanly.
- `os.time()` counts from boot, as `CLOCK_REALTIME` does until there is a wall clock (`docs/milestones/known-gaps.md`).

## Consequences

- Upgrading is replacing the tree with the next release's and checking `src/Makefile`'s lists and flags against `port.ndb`.
- Lua's code is not under the house rules (04 §1.1); it builds with its own flags and warnings, and `./build check` does not lint it, as for musl.
